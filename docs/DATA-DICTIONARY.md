# 数据字典 mixcredit

## 金额与精度

| 项 | 定义 |
|---|---|
| 内部存储 | 整数分（`int`），字段名以 `_cents` 结尾 |
| 对外展示 | 元，两位小数，千分位分隔 |
| 导出 | CSV 给整数分；JSON 在 `money.unit` 声明单位为分 |
| 取整 | `Decimal` + `ROUND_HALF_UP` 到分，再乘 100 取整 |
| 拆分 | 整数分 + 最大余额法，拆完必须等于原额（差额 0） |
| 大整数 | 订单号、触点编号、账号一律字符串，不过 `int()` |

## 时间

| 项 | 定义 |
|---|---|
| 列 | `event_time`、`ingested_at`、`order_time` |
| 可接受写法 | `...Z`、`...+08:00`、无偏移（按 +08:00 解释，`kind=naive`） |
| 存储 | 统一转 UTC，ISO 8601，导出带 `Z` |
| 展示 | 页面按 +08:00 显示，报告页标注时区 |
| 窗口 | 半开区间 `[t-窗口, t)`：左端计入，右端（下单同一时刻）不计入 |

## 窗口与事件

| 事件类型 | 窗口 | 含义 |
|---|---|---|
| `click` | 7 天 | 下单前 7 天（含）到下单前一刻的点击 |
| `impression` | 1 天 | 下单前 1 天（含）到下单前一刻的曝光 |
| 迟到 | 不限 | 入库时间晚于下单时间 → 仍计入，`late=1` |
| 窗口外 | 不限 | 不在任何窗口内 → 状态 `DROPPED`，原因码 `OUT_OF_WINDOW` |

## 渠道与事件类型

| 代码 | 名称 |
|---|---|
| `douyin_feed` | 抖音信息流 |
| `xhs_seed` | 小红书种草 |
| `wechat_moments` | 微信朋友圈 |
| `baidu_search` | 百度搜索 |
| `tmall_ads` | 天猫直通车 |
| `private_group` | 私域社群 |

事件类型只有 `click`（点击）与 `impression`（曝光）。

## 空值与哨兵

`SENTINELS` 只在 `app/modules/m2_window/contract.py` 定义一处：
空串、`-`、`—`、`--`、`N/A`、`NA`、`NULL`、`NONE`、`NAN`、`未知`、`无`、`空`。

- 触点的 `cost` 是哨兵 → 成本记为 `null`，触点仍可计入。
- 订单的 `gmv` 是哨兵 → 订单进隔离区，原因码 `OD_GMV_INVALID`。
- 大小写不敏感（`n/a` 与 `N/A` 等价），中文哨兵原样比较。

## 单位

| 列 | 单位 | 处理 |
|---|---|---|
| `cost` | 元 | 支持 `万元` 后缀，先归一到元再取分 |
| `gmv` | 元 / 万元 | `unit` 列优先；无单位列时看数值后缀 |

## 去重键

| 表 | 业务键 | 冲突时 |
|---|---|---|
| 触点 | `touch_id` | 字段不同 → 全组隔离 `TD_TOUCH_DUP_CONFLICT`；字段相同 → 保留首条，其余 `TD_TOUCH_DUP_IDENTICAL` |
| 订单 | `order_id` | 金额不同 → `OD_DUP_CONFLICT`；相同 → `OD_DUP_IDENTICAL` |
| 别名 | `alias_id` | 并查集合并，不隔离 |

## 归因模型

| 代码 | 名称 | 权重 |
|---|---|---|
| `first` | 首次触点 | 最早一条 100% |
| `last` | 末次触点 | 最晚一条 100% |
| `linear` | 线性均分 | 全部等权 |
| `time_decay` | 时间衰减 | `2^(-距今/3.5天)`，3.5 天衰减一半 |
| `position` | 位置加权 | 首 40%、末 40%、中间平分 20%；两条各 50% |

## 预算

| 项 | 定义 |
|---|---|
| 总额 | 用户提交的 `total_yuan`，转整数分 |
| 下限/上限 | `sample_data/budget_plan.json` 的 `min_yuan` / `cap_yuan` |
| 加档 | 每次 1000 元，给边际 ROI 最高的渠道 |
| 边际 ROI | `基础 ROI / (1 + 0.15 × 已加档数)`，同分按渠道代码升序 |
| 版本 | 必须等于当前最大版本 + 1；小于等于已存在版本 → 409 |
| 守恒 | 各渠道新预算合计 = 总额，差额必须为 0 |

## 置信区间（M7）

| 项 | 定义 |
|---|---|
| 抽样单位 | 订单簇（一单一条），不按份额行抽 |
| 帧 | 只收 `status=OK` 的订单；同一订单号多行时取 `row_no` 最小的有效行 |
| 簇内次序 | 触点按 (`event_time_utc`, `touch_id`) 升序，同一秒用编号定序 |
| 簇内金额 | 与 M4 同一套权重，整数分 + 最大余额法，簇内合计 = 该单成交额 |
| 抽样次数 | 20–2000，默认 200，每次抽的簇数与帧内簇数相同，有放回 |
| 种子 | 0–2147483647，默认 638；线性同余流，同种子同结果 |
| 区间 | 默认 90%（`alpha_pct=10`），分位取排序后第 `floor(q×(N-1))` 个 |
| 份额 | 渠道金额 ÷ 该次抽样合计，两位小数；点估计用整帧合计 |
| ROI | 渠道金额 ÷ 渠道花费，两位小数；花费为 0 时不给区间 |
| 首位 | 每次抽样金额最大的渠道，同额取渠道代码升序 |
| 首位保持 | 首位渠道在全部抽样中出现次数 ÷ 抽样次数 |
| 半宽 | (区间上限 − 区间下限) ÷ 2，单位百分点 |
| 判「不稳」 | 簇数 < 8、半宽 > 5 个百分点、首位保持 < 90%、前两渠道区间重叠，任一命中 |
| 预算对齐 | 最新方案的加投首位与份额首位相同记「一致」，不同记「不一致」并加码 |

帧摘要取 `sha256(model + 簇的订单号与渠道金额)`，同一份证据重算得到同一个值。

## 空态

| 状态码 | 含义 | 结论 |
|---|---|---|
| `empty` | 文件 0 字节 | 运行失败，`stats` 全 0 |
| `header_only` | 只有表头 | 运行失败，不产生证据行 |
| `blank_rows` | 有行但全是空行 | 运行失败 |
| `truncated` | 末行被切断 | 运行时照常处理，半行隔离，文件级状态标记截断 |

## 原因码

| 码 | 含义 | 级别 |
|---|---|---|
| `TD_COL_COUNT` | 列数不齐或编号缺失 | 隔离 |
| `TD_TIME_UNPARSABLE` | 事件时间无法解析 | 隔离 |
| `TD_CHANNEL_UNKNOWN` | 渠道缺失或不在白名单 | 隔离 |
| `TD_EVENT_TYPE_UNKNOWN` | 事件类型未知 | 隔离 |
| `TD_COST_INVALID` | 成本无法解析或为负 | 隔离 |
| `TD_TOUCH_DUP_CONFLICT` | 触点编号重复且字段冲突 | 隔离 |
| `TD_TOUCH_DUP_IDENTICAL` | 触点编号重复且内容相同 | 隔离 |
| `OD_TIME_UNPARSABLE` | 订单时间无法解析 | 隔离 |
| `OD_GMV_INVALID` | 订单金额无法解析 | 隔离 |
| `OD_DUP_CONFLICT` | 订单号重复且金额冲突 | 隔离 |
| `OD_DUP_IDENTICAL` | 订单号重复且内容相同 | 隔离 |
| `FILE_TRUNCATED` | 文件截断 | 失败 |
| `FILE_EMPTY` | 文件为空 | 失败 |
| `FILE_HEADER_ONLY` | 仅有表头 | 失败 |
| `FILE_BLANK_ROWS` | 全部为空行 | 失败 |
| `ALIAS_BAD_ROW` | 别名行不完整 | 隔离 |
| `OUT_OF_WINDOW` | 不在归因窗口内 | 不计入 |
| `CI_DUP_ORDER_KEPT` | 同一订单号多行只算一次 | 结论 |
| `CI_FRAME_EMPTY` | 没有可重采样的订单 | 结论 |
| `CI_FRAME_THIN` | 订单簇少于 8 单 | 结论 |
| `CI_WIDE_INTERVAL` | 份额区间半宽超过 5 个百分点 | 结论 |
| `CI_UNSTABLE_RANK` | 首位渠道在重采样中不稳 | 结论 |
| `CI_INTERVAL_OVERLAP` | 前两渠道区间重叠 | 结论 |
| `CI_BUDGET_MISMATCH` | 预算首位与份额首位不一致 | 结论 |
| `CI_SAME_SECOND_TIE` | 同秒触点按编号定序 | 结论 |

一行命中多条时按上表序号取最小者，与规则书写顺序无关。
